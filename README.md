# Boss Shop

Десктопная программа для Windows 7, 8, 8.1, 10 и 11 (64-bit): товары, склад, продажи, возвраты, расходы и чистая прибыль магазина мужской одежды.

## Версия 1.3.4

В «Товары и остатки» убраны колонки «Штрихкод» (также у раскрытых вариантов) и «Вариантов». Сортировка размеров, цветов, остатков и цен внутри модели сохранена. Штрихкоды старых товаров остаются в базе, поиске и карточке.

**Автоматические номера.** При ручном создании модели номер присваивается серверной частью в транзакции сохранения; все размеры/цвета имеют один «№ товара». Ручного обязательного артикула и его быстрого редактора больше нет. Номер записывается в совместимое поле `article`, признак нового номера — `auto_number`, верхняя граница — в отдельном сохраняемом `catalog_sequence`. Удаление и перезапуск не освобождают номер; ошибка транзакции не расходует его. Переданные вручную артикул/номер новой модели не заменяют автоматическую нумерацию. Добавление варианта сохраняет номер модели.

Существующие товары и снимки документов не перенумеровываются: у них показан «Артикул» / «Прежний артикул», у новых — «№ товара». Поиск находит оба; экспорт разделяет эти поля. Изменение прежнего артикула или присвоенного номера через карточку/API запрещено. Excel/CSV продолжает сопоставлять старые товары по внешнему артикулу и размеру/цвету. Числовые внешние артикулы (включая ведущие нули) повышают сохраняемый счётчик. Если артикул импорта совпал с автоматическим номером ручного товара, весь импорт отклоняется с объяснением: нужен другой внешний артикул. Это предотвращает незаметное смешение внешних артикулов и ручного каталога. Повторный импорт по прежним внешним артикулам остаётся идемпотентным в режиме «Установить как в файле».

**Фото модели.** Кнопка «Карточка модели / фото» или карточка варианта позволяет выбрать файл, увидеть превью, заменить или убрать фото; оно общее для всех размеров/цветов. Миниатюра открывает увеличенное изображение и доступна продавцу без закупочных данных. Принимаются JPEG/PNG/WebP до 10 МБ, до 12000 пикселей по стороне и 40 мегапикселей. Проверяются заголовок, размеры и реальное декодирование; изображение уменьшается до 1200 px и пересохраняется в JPEG до 600 КБ без исходных метаданных. WebP обрабатывается в скрытом sandbox-окне Chromium без Node, файловых путей и сети. Исходные файлы не копируются; в SQLite хранится только ограниченный data URL. Фото переносится полной `.bossshop` копией и восстанавливается после перезапуска. Списки не передают исходное изображение при каждом поисковом вводе; фото загружаются отдельно с ограниченным кэшем. «Отмена» карточки не записывает выбранное/удалённое фото. Пустые старые карточки поддерживаются.

**Полное удаление модели.** Администратор нажимает корзину в строке модели. Подтверждение называет модель, номер/прежний артикул, число всех вариантов и общий остаток; предупреждает о необратимости и недоступности будущего возврата. Удаляются сама модель, все её варианты (включая ранее скрытые), фото и ненулевые остатки. Отдельной кнопки удаления варианта и новых действий архивирования товаров нет. «Показать ранее скрытые позиции» позволяет явно удалить старые архивные записи; миграция их не удаляет. Аудит сохраняет автора, модель, варианты, количество и точную стоимость удалённого остатка. Удаление каталога не создаёт финансовый документ списания и не меняет суммы уже проведённых документов.

Продажи, оформленные возвраты, поступления, списания, складская история, аудит и отчёты сохраняются. Миграция отделяет их от удаляемого каталога: `variant_id` становится nullable с `ON DELETE SET NULL`, добавляются снимки реквизитов истории; первичные ID, ограничения, индексы и последовательности сохраняются. ID каталога тоже не переиспользуются. Внешние ключи отключены только на время транзакции перестройки таблиц, проверяются до сохранения и включаются обратно при успехе/откате. Отказ записи откатывает миграцию или удаление; `.previous` и автокопии продолжают работать.

**Ограничение для удалённых позиций:** новый возврат такой строки запрещён с понятным объяснением; скрытый архив не создаётся. В редакторе продажи нельзя менять/удалять её товар, количество или цену. Реквизиты продажи (дата, оплата, сотрудник, комментарий) и другие строки без возвратов/удалённого товара доступны; историческая себестоимость и старые возвраты сохраняются. Повторный импорт ранее удалённого внешнего артикула явно создаёт новый товар и не присоединяет к нему старые документы.

Проверки 1.3.4: `npm test` включает миграцию заполненной старой схемы, номера после удаления/перезапуска/импорта, коллизии, отказ записи, фото в полной копии, документы после удаления и `foreign_key_check`. `npm run test:electron` использует только временный профиль и файлы: настоящий main/preload/renderer, выбор и декодирование JPEG/PNG/WebP, превью/сохранение/замена/удаление/отмена фото, колонки для обеих ролей, подтверждение/отмена удаления, исторические документы, backup/restore и реальный перезапуск. Нативные диалоги в тесте подставляют временные пути; реальная пользовательская база не используется.

### Сохранённые возможности 1.3.3

Категория и бренд в «Товары и остатки» имеют отдельные колонки, фильтры и быстрые редакторы; подкатегории сохранены. В раскрытой модели заголовки размера, цвета, остатка и цен сортируют только варианты внутри каждой модели. Размеры сортируются с учётом чисел и порядка XS/S/M/L/XL/XXL; направление обозначено стрелкой.

Новую модель можно создать сразу со списком размеров: введите размеры через запятую, точку с запятой или перевод строки, либо добавьте их из справочника и нажмите «Распределить размеры». Повторы списка объединяются, порядок ввода сохраняется в таблице. У каждого варианта доступны цвет, начальный остаток, закупочная/розничная цена и штрихкод. Новые размеры добавляются в справочник. Модель, варианты, стоимость и начальные движения сохраняются одной транзакцией; существующий артикул не перезаписывается. Кнопка «+» в строке модели добавляет один вариант, карточка прежнего варианта продолжает работать.

Администратор редактирует дату, оплату, сотрудника и комментарий продажи прямо в таблице, а товары, количество и цены — через «Изменить состав». Продавец создаёт продажи, но не редактирует проведённые и не получает закупочные цены/прибыль. Продажа выбирается и показывается только по календарной дате (также в возвратах, истории и экспорте); старые сохранённые времена не мигрируются. Фильтры включают весь выбранный день без преобразования через UTC.

Правка продажи атомарно обновляет склад, `stock_cost`, историю, суммы отчётов и аудит с автором и данными до/после. Смена только цены не меняет историческую себестоимость. Увеличение количества сохраняет прежнюю стоимость и добавляет стоимость дополнительных единиц по текущему средневзвешенному остатку. При уменьшении историческая стоимость распределяется пропорционально, разница возвращается на склад. Замена товара восстанавливает прежние единицы по снимку и списывает новый товар по его текущей стоимости. Снимки остальных строк и их идентификаторы сохраняются. Это исправление документа, а не перепроведение последующих продаж и поставок.

**Ограничение при возвратах:** у строки с любым возвратом запрещены смена товара, цены, количества и удаление (в том числе уменьшение ниже возвращённого). Можно менять реквизиты продажи и другие строки без возвратов; связь и суммы прежних возвратов сохраняются. Изменённый параллельно документ требует повторного открытия. Повторные строки, недостаточный остаток, неверные даты/суммы отклоняются серверной частью; ошибка записи откатывает всю правку. Повторное нажатие создания из той же формы защищено ключом операции.

Новые целевые тесты входят в `npm test`; изолированный `npm run test:electron` проверяет также отдельные колонки, сортировку внутри модели, создание размеров, редактор продажи и дату без времени на реальном renderer/preload/main с временным профилем.

Выпуск включает безопасное сохранение sql.js с проверенной предыдущей версией `.previous` и автокопиями, защиту от одновременного запуска второго экземпляра, средневзвешенную себестоимость остатков (`stock_cost`) с миграцией старой базы и точные частичные возвраты. Закупочный импорт суммирует стоимость сгруппированных строк без потери копеек; отчёт можно сохранить в файл.

## Возможности

- связанные справочники категорий, подкатегорий, размеров, поставщиков и сотрудников;
- варианты товара по размеру и цвету, поиск и фильтры, предупреждения о низком остатке;
- поступления, продажи, возвраты и списания с автоматическим изменением склада;
- сохранение закупочной и розничной цены на момент продажи;
- расходы, аренда и зарплата с указанием отчетного периода;
- dashboard за день, неделю, месяц, квартал, год или произвольный период;
- аналитика по категориям, товарам, размерам и брендам;
- отчет «Прибыль и убытки» и расчет маржинальности;
- история складских операций;
- экспорт таблиц и отчетов в Excel, CSV и PDF;
- импорт товаров, цен и остатков из Excel `.xlsx` и CSV с предварительным просмотром;
- отчёт по импорту с причинами пропуска строк; загрузка закупочных цен без изменения остатков;
- четыре размера шрифта интерфейса с сохранением выбранного масштаба;
- поиск товаров без учета регистра, группировка размеров и цветов, сортировка и быстрый сброс фильтров;
- редактирование отдельных полей прямо в таблице товаров без открытия карточки; цены можно менять для одного варианта или сразу для всех размеров и цветов товара;
- исправление остатка прямо в таблице с записью корректировки в историю склада;
- предупреждение о неизвестной себестоимости и защита отчета от недостоверного расчета прибыли;
- полная резервная копия всех данных в один файл и восстановление с автоматической проверкой;
- роли «Администратор» и «Продавец». Продавцу недоступны закупочные цены, расходы и прибыль;
- локальная SQLite-база, работа без сервера и интернета.
- единая 64-битная сборка для старых и современных версий Windows.

## Данные и резервная копия

Рабочая база хранится в профиле текущего пользователя Windows, в каталоге приложения `boss-shop`, файл `boss-shop.sqlite`. Для резервной копии закройте программу и скопируйте этот файл в безопасное место. История продаж сохраняется при полном удалении товара и архивировании справочников.

Для штатного резервного копирования откройте «Настройки → Защита данных» и нажмите «Сохранить в файл». Программа создаст файл `.bossshop`, содержащий всю базу. Кнопка «Восстановить из файла» проверяет целостность выбранной копии, автоматически сохраняет текущую базу как аварийную копию и перезапускает приложение с восстановленными данными. Эти операции доступны только администратору.

### Надёжное сохранение и автоматические копии

Программа допускает только один экземпляр для профиля; повторный запуск показывает и фокусирует первое окно, восстанавливая его из свёрнутого состояния. База sql.js хранится в памяти и сохраняется целиком: новый файл записывается рядом с рабочим, сбрасывается на диск (`fsync`) и заменяет рабочий через переименование без удаления исходного файла. Рядом остаётся проверенная предыдущая версия `.previous`. Ошибка записи отменяет операцию и восстанавливает прежнее состояние в памяти; повторная попытка не проводит документ дважды.

При запуске проверяется целостность рабочей базы. Если она отсутствует или повреждена, программа использует пригодную `.previous`, затем последнюю пригодную автокопию. Повреждённый исходный файл сохраняется как `.damaged-*`; источник восстановления виден в настройках. Незавершённые `.pending-*` не принимаются за подтверждённые данные. Если пригодных копий нет, повреждённая база не заменяется пустой: запуск останавливается с сообщением об ошибке. После аварийного завершения последняя операция может быть уже сохранена, даже если пользователь не успел получить подтверждение; перед повторным вводом проверьте историю.

Автокопии `.bossshop` находятся в `boss-shop.sqlite-autobackups` рядом с базой. Проверенная существующая база копируется при запуске (до миграций), затем копия создаётся после успешного сохранения изменений не чаще раза в час. Хранятся последние 14 автокопий. Новая копия записывается до удаления старых; ручные копии и копии перед восстановлением не участвуют в ротации. «Настройки → Защита данных» показывает каталог, количество, последний файл, ошибки копирования и факт аварийного восстановления. Ошибка автокопирования не отменяет уже сохранённую рабочую операцию.

Ручной `.bossshop` backup/restore сохраняет прежний формат. Перед восстановлением создаётся аварийная копия текущих данных, а замена рабочей базы использует тот же безопасный механизм. Автокопии на том же диске не защищают от поломки диска: сохраняйте ручные копии на другой носитель. `fsync` файла применяется всегда; сброс каталога выполняется, когда файловая система Windows его поддерживает. Тесты аварийного завершения процесса не доказывают сохранность при физическом отключении питания или отказе накопителя.

### Средневзвешенная себестоимость

Деньги хранятся целыми копейками. Для каждого размера/цвета дополнительно хранится общая стоимость текущего остатка (`stock_cost`). Поступление добавляет `количество × цену поставки` к стоимости старого остатка. Например, 2 шт. по 100 ₽ и 3 шт. по 200 ₽ дают 5 шт. стоимостью 800 ₽ и среднюю цену 160 ₽.

Средняя цена в карточке — округлённая стоимость единицы. Продажа и списание распределяют точную стоимость пропорционально количеству: `округлить(стоимость остатка × количество / остаток)`. Округление до ближайшей целой копейки, ровно половина копейки — вверх. Промежуточные вычисления используют целые числа `BigInt`; выход за безопасный диапазон отклоняется. Оставшиеся копейки сохраняются в остатке; при полном выбытии его количество и стоимость равны нулю. Поэтому стоимость строки продажи иногда отличается от округлённой средней цены, умноженной на количество.

Возврат добавляет в склад стоимость из снимка исходной продажи, а не сегодняшнюю закупочную цену. Для частичных возвратов используется накопленное пропорциональное округление минус стоимость уже оформленных возвратов: полный возврат точно возмещает стоимость строки продажи. Уже записанные документы, цены и суммы не пересчитываются; меняется только счётчик возвращённых единиц при новом возврате.

- Ручное изменение закупочной цены в карточке или таблице переоценивает **весь текущий остаток**: количество × новая цена. Сохранение той же отображаемой цены не стирает остаточные копейки. Для новой партии с другой ценой оформляйте поступление.
- Ручная коррекция количества вниз снимает пропорциональную стоимость; вверх добавляет единицы по текущей округлённой средней цене. История фиксирует коррекцию.
- Импорт с режимом «Добавить к текущим» усредняет старую стоимость с закупочной стоимостью новых единиц. Если импортируется только розничная цена, добавленные единицы оцениваются по текущей средней закупочной цене.
- Если одинаковый вариант встречается в файле по разным ценам, закупочная стоимость строк суммируется точно; «Добавить» и «Установить» сохраняют эту сумму без потери копеек. Для «Не менять остатки» используется округлённая средняя закупочная цена из файла. Розничная цена по-прежнему берётся из последней строки. Предпросмотр показывает цену по выбранному режиму.
- Импорт закупочной цены с «Установить как в файле» переоценивает весь итоговый остаток по цене файла; с «Не менять остатки» переоценивает существующий остаток без изменения количества. Импорт только розничной цены сохраняет стоимость оставшихся единиц и изменяет количество по правилам коррекции.
- При нулевом остатке цена остаётся справочной для ручного добавления, но следующая поставка формирует стоимость только из новой партии. Нулевая закупочная цена сохраняет принятую в программе трактовку «себестоимость не указана»; импорт только розницы не восстанавливает неизвестную закупочную цену.

Миграция старой базы выполняется одной сохраняемой транзакцией: текущая стоимость инициализируется как остаток × прежняя закупочная цена. Старые поставки, продажи, возвраты и списания не меняются. Восстановить настоящую стоимость смешанных партий задним числом из прежней единственной цены невозможно; при необходимости администратор корректирует текущую цену вручную.

Проверка Electron с временным профилем (после `npm run build`): `npm run test:electron`. Обычные `npm test` также используют только временные синтетические базы, включая прерывания процесса и имитацию ошибок записи.
